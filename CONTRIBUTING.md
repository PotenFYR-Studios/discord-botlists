# Contributing to discord-botlists

Thanks for helping improve the universal Discord botlist SDK. This guide covers everything you need to get a PR merged.

## Project rules (non-negotiable)

1. **Zero runtime dependencies.** The library runs on Node builtins only. No new `dependencies` in `package.json`; devDependencies for tests/docs are fine.
2. **Generated files are never hand-edited:**
   - `src/data/lists.generated.ts`: regenerate via `scripts/snapshot/build_lists.py`
   - the README block between `<!-- STATUS:START -->` and `<!-- STATUS:END -->`: regenerated by `scripts/status-sync.ts`
   - `docs/src/docs/version.generated.ts`, `docs/src/data/status.json`: generated at docs build time
3. **No breaking API changes without a major version bump.**
4. **Every botlist fact must be verifiable**: endpoints, field names and auth headers come from the list's own docs or the BotBlock snapshot, not guesswork.

## Setup

You need [Bun](https://bun.sh) 1.1+ (and Node.js 18+ is what the published package targets).

```bash
git clone https://github.com/PotenFYR-Studios/discord-botlists.git
cd discord-botlists
bun install --frozen-lockfile
```

## Commands

| Command | What it does |
| --- | --- |
| `bun run lint` | Typecheck (`tsc --noEmit`) |
| `bun run build` | Compile the library to `dist/` |
| `bun test` | Unit tests (no network) |
| `bun scripts/test-live.ts` | Live integration test against real botlists (optional, reads `.env`) |
| `bun run dev` (in `docs/`) | Docs site dev server (see below) |

For the live test: `cp .env.example .env`, then fill tokens for the lists you use (all optional; lists without tokens are skipped). It fetches real data, posts a server count of 1, and simulates a webhook, printing PASS/FAIL per action.

## Repository layout

```
src/               the npm library (@potenfyrstudios/discord-botlists)
  core/            HTTP client, retries, rate limit safety
  webhooks/        VoteWebhookServer (signature checks, rate limits, bans)
  status/          StatusChecker (hourly probes)
  data/            lists.generated.ts (registry, generated)
  parsers/         UniversalParser -> UniversalBot
test/              unit tests (bun test) + node compatibility tests
scripts/           status-sync, gen-version, snapshot builder, live test
docs/              documentation site (Vite + React), deployed to
                   https://botlists.docs.potenfyr.in via GitHub Pages
.status/           generated probe results (status.json, shield.json, STATUS.md)
```

## Adding or fixing a botlist

The registry is generated from a BotBlock snapshot plus manual overrides.

```bash
# 1. refresh the snapshot
curl -s https://botblock.org/api/lists > scripts/snapshot/botblock-lists.json

# 2. edit overrides in scripts/snapshot/build_lists.py
#    (endpoints, post fields, auth headers, webhook formats)

# 3. regenerate and verify
python3 scripts/snapshot/build_lists.py
bun test
```

Open the PR with the list's API docs linked so a maintainer can verify the wire format. To report a list as dead, use the [botlist request template](https://github.com/PotenFYR-Studios/discord-botlists/issues/new?template=list_request.yml) instead; the hourly status sync will pick it up.

## Working on the docs site

```bash
cd docs
bun install --frozen-lockfile
bun run dev      # vite dev server with HMR
bun run build    # production build (includes static prerender of every route)
```

Versioned docs content lives in `docs/src/docs/content.tsx`. New doc versions are created by copying the latest version block and updating `DOC_VERSIONS`; the static build and the ⌘K palette pick them up automatically from `version.generated.ts`.

## Commits and PRs

- **Conventional Commits**: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`. [release-drafter](.github/release-drafter.yml) builds the changelog from these.
- Keep PRs focused; one list/feature/fix per PR.
- The PR template's checklist is the review bar: run lint, build and tests before pushing.

## Reporting bugs and security issues

- Bugs: [bug report template](https://github.com/PotenFYR-Studios/discord-botlists/issues/new?template=bug_report.yml)
- Vulnerabilities: **never** in a public issue: see [SECURITY.md](SECURITY.md) for private reporting.
